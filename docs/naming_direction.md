# 名堂 · 起名逻辑重构方向

> 来源：与产品 owner 的深度访谈（2026-08-27）
> 性质：产品方向共识，指导后续起名逻辑的改造

---

## 一、产品共识（访谈结论）

1. **名字是"替孩子做的第一个决定"**，核心焦虑是"怕不够好"。工具要帮用户建立一套能让自己信服的标准，填补"孩子还没法参与、没法说喜欢"的空缺。
2. **好名字 = 美好 + 印象深刻 + 不落俗套**，三者里最难、最核心的是"不落俗套"。
3. **"不落俗套"的本质是「有余味、有出处、有故事」**，不是好词的堆砌。用户要的是一个字背后藏着一层甚至几层意思、第一眼好看、第二眼还能品出东西的名字，而不是吉祥字拼一起、一眼看穿的堆砌。
4. **含义/意象是唯一核心，生僻字不设限、也不加分**。不追求生僻；但意象极美、有来处、有余味的字，即便不那么常见，也不该因为"生僻"被筛掉。

---

## 二、核心理念转变（最重要的定位调整）

**「韵味是核心，音律/五格/八字只是为了缩小筛选范围。」**

从当前的「加权平均」模型，改为「漏斗筛选」模型：

```
3540 字
  │
  ├─ 第一层门槛：音律、五格、八字 —— 只做"排除"，不做"打分"
  │    （排除明显不合格：读音严重拗口 / 五格大凶 / 八字忌神严重冲突）
  │
  ├─ 通过门槛的候选
  │
  └─ 第二层排序：韵味（含义 / 意象 / 出处 / 余味）—— 决定谁排前面
```

**关键变化**：音律、五格、八字不再是"和韵味平起平坐的评分维度"，而是"把明显不合适的人先筛掉"的粗筛器。最终决定推荐顺序的，是名字本身有没有味道。

---

## 三、选词范围

**现有**：诗经、楚辞、唐诗、宋词、汉魏古诗、经史子集

**新增**：周易、本草纲目、神农本草经、山海经

- 山海经：植物、神兽、地名（如 望舒、扶苏、杜若）
- 本草纲目 / 神农本草经：中药名（如 徐长卿、白芷、青黛、半夏、杜若、白薇、黄芪）——大量意象极美的字源，且是差异化方向
- 周易：已有部分（经史子集内），需强化

## 四、改进点（按优先级）

1. **重定义"好名字"标准**：把「含义美、有出处、有余味」设为第一标准；安全、常用降为底线（不再是目标）。

2. **评分从「加权平均」改「漏斗筛选」**：
   - 音律 / 五格 / 八字 → 门槛（硬性排除明显不合格，不做主排序）
   - 韵味 → 核心排序（含义深度、意象质量、出处余味）

3. **字的选择放开**：负面字黑名单仍保留（安全底线，杜绝"张竹匪"类事故）；但不再因"生僻、不常用"而降权，意象美的字放行。

4. **寓意解读要"讲出余味"**：名字详情/寓意不再模板拼接"出自XX·XX"，而是讲出这个名字藏了几层意思（复用 LLM，当前 LLM 链路已通，尚未接入起名寓意）。

5. **扩展字源**：接入本草纲目、神农本草经、山海经的意象字源（与现有诗词库并列，作为新的"出处"来源）。

## 七、2026-09-20 整改：语境字义 + 分层抽样（已实施）

> 起因：评审实测发现「不同生日 / 不同期待 → 推荐名字高度相似」。
> 量化证据：不同输入的 Top100 重合 38~49%；600 个名字仅用 217 个字，Top20 字占 40%；
> 同一名字跨 18 组输入重复出现 7 次。根因是**主排序键（韵味分）与用户输入无关**，
> 且**字义被当作静态属性**（同一字在不同诗句里含义不同，系统只取该字的字典义）。

### 7.1 语境字义（同一字 · 不同诗句 → 不同义项）

- 新增数据 `data/sense/char_senses.json`：对每个「字 × 出处」对，标注该字在该句语境中的取义。
  生成脚本 `scripts/sense_annotator.py`（LLM 批量标注，asyncio 并发 + 断点续跑 + 原子落盘），
  提示词 `scripts/prompts/sense_prompt.py`。
- 全量标注完成：1286 个「字×出处」对，1251 条义项记录，覆盖 466 字，零失败。
  人工抽检 80 条，准确率 95%（元描述类误标已通过过滤规则清洗）。
- 读层 `app/services/char_sense_database.py`（单例，缺失文件时降级为空索引）。
- 打分接入 `app/services/yunwei_scorer.py`：
  - I（意象）/ L（余味）改为**语境优先**——有语境义项用语境义项，否则回退字典义；
  - L（余味）与出处绑定（同一字在不同出处的余味层数不同）。
- 展示接入：`/name/meaning` 与起名结果均返回 `context_senses`
  （`[{"char","senses","general","from_main"}]`），详情页「用字解析 / 诗词出处」按语境释义；
  `from_main=false` 表示该字不在名字主出处里、义项取自它自己最贴合的一句。

### 7.2 主排序改造：分层抽样（替代整体加权采样）

- 偏好**硬分流**：给了寓意/风格时，命中偏好的名字先占 `min(k, TARGET_MIN)` 席位。
- 八字**分层配额**：其余名额按 `全喜神层 : 含非喜用神层 = 8 : 2` 分配。
  注意：`BaziEngine` 的忌神恒为喜神补集，因此**不存在「中性字」**，
  原「用神/喜神/中性」三层里中性层恒为空；现改为两层，用神命中作为层内权重加分。
- 层内权重 = 韵味分 + 用神命中加分（随生日变化）→ 兼顾质量、多样、抗「常客」。
- 候选池放大：组合阶段候选池由 120 扩到 ≈970（`COMPOSE_*` 系数），
  否则「从 160 个候选里抽 30」导致高频常客不可避免。参数集中在 `NamingEngine` 类常量。

### 7.3 用字质量闸门（出处白名单）

- 候选字必须是「诗词/古文出处推荐过的字」并集（477 字）里的字，否则会出现
  「订 / 切 / 叫 / 口 / 轧」这类无出处、无字义的字被按笔画归入某五行后混进名字。
- 例外：情绪字（哀悲愁怨恨怒）仍进候选池（尊重「分级放开」的既有决定），
  但软门槛改为「**该字本身**须有出处 + 名内非全情绪字」——
  数据中情绪字均无出处，故实际不会出现在结果里。

### 7.4 量化验收（`scripts/eval_naming.py`）

样本：18 组不同出生日期 × Top30，共 540 个名字。

| 指标 | 整改前 | 整改后 |
|------|--------|--------|
| 跨输入重合率（不同生日两两平均） | 38~49%（Top100） | **1%** |
| 用字集中度（不同字 / Top20 字占比） | 217 字 / 40% | **329 字 / 20%** |
| 高频常客（18 组中最高重复） | 7 次 | **3 次**（受组合数学上限约束，已接近可达下限） |
| 八字匹配度（用字命中喜用神） | — | **90%** |
| 偏好生效度（不同寓意两两重合） | 选不选一样 | **5%** |
| 换一批变化（同输入两次重合） | — | **0~10%** |
| 语境义项覆盖 | 0% | **100%** |

> 注：上表为 7.1~7.3 实施后的第一轮结果。第八节的质量整改会改写其中
> 「用字集中度 / 高频常客 / 换一批」三项，请以第八节表格为准。

### 7.5 顺带修复的性能/正确性问题

- 拼音计算加缓存（`PhoneticsScorer.get_pinyin`、`SurnameFit._plain_pinyin`）；
- 诗词库/字源库新增**按字倒排索引**（`get_by_char` 由 O(N) 线性扫描降为 O(1)）；
  两项合计使起名耗时由约 1.2s 降到 **0.28s**，从而能够负担更大的候选池。
- 出处择优：多条出处时按「字是否出现在原文 / 是否有语境义项」择优，
  不再盲取第 0 条（`_entry_fit_score` / `_pick_entry_for_char`）；
  随机组合优先取「同源搭档」，让随机组合的名字也「有据可循」。
- 来源推荐（`recommend_sources`）分层由「命中/未命中」二分改为**按命中强度分档**，
  并让「偏好命中优先于忌神避让」——原实现忌神覆盖 5 行中的 3 行、沉底 75% 的来源池，
  导致两种偏好给出几乎相同的来源（重合 26/30）；现降到 **3/30**。

## 八、2026-09-20 二次整改：尾部弱名（质量带宽）

> 起因：7.1~7.4 实施后联调实测，发现返回列表**尾部名字韵味仅 28~44**
> （如「李同情 / 李珠刚 / 李取伦 / 李宇王」），而头部有 70+，观感割裂。
> 诊断结论：**与八字、偏好、用神加分都无关**——提高或去除用神加分、扫描温度，
> 尾部最低分在所有配置下都卡在 28~44（`scripts/sweep_stratify.py`）。

### 8.1 根因：候选池是双峰的，而抽样对两峰一视同仁

诊断脚本 `scripts/diag_pool_quality.py`：拆开进入分层抽样前的候选池——

| 类型 | 判据 | 池内条数 | 平均韵味 |
|------|------|---------|---------|
| **同源名** | 双字同出一源（出处分 P=35） | 326~458 | **63.4~64.0** |
| **单字名** | 仅一字有出处（P=20） | 196~550 | **44.2~46.8** |

单字名占了池子一半，均分比同源名低近 20 分。原来的层内抽样温度 T=26
在这两峰之间近似均匀抽样，于是低峰被大量抽进 Top30 —— 这就是弱尾。

### 8.2 修法：质量带宽 + 职责分离

- 新增 `STRATIFY_QUALITY_BAND = 18`：抽样窗口内只保留
  「韵味分 ≥ 窗口最高分 − 18」的名字，正好卡在两峰之间，把单字名挡在抽样之外。
  带宽按**窗口最高分**取相对值而非绝对值，以适配不同生日的池子。
- `STRATIFY_TEMPERATURE` 26 → **36**：温度只负责多样性（不再兼任质量调节），
  实测 T>36 多样性收益递减且八字匹配度下滑。
- `STRATIFY_YONG_BONUS` 60 → **20**：带宽把每层候选压到百来个之后，+60/用神字
  （双用神字最多 +120）会让抽样极度集中到「双用神字」子集上（换一批重合 33%）。
  实测该加分**对八字匹配度毫无贡献**——匹配度 90% 完全由分层配额保证，
  故取小值仅保留「用神进入主排序权重」的设计意图。
- `STRATIFY_BAND_MIN_FACTOR = 3`：带宽后的候选不足 `n × 3` 时不启用带宽，
  避免窗口过窄使抽样退化为确定性排序。

### 8.3 量化验收（同一 `scripts/eval_naming.py`，18 组 × Top30 = 540 名）

| 指标 | 一次整改后 | **二次整改后** | 目标 | 结论 |
|------|-----------|--------------|------|------|
| 韵味 min / p5 / 中位 | 28 / 40 / 52 | **58 / 58 / 66** | — | 达标 |
| **低于 50 分的名字条数** | **235**（44%） | **0** | — | 达标 |
| 双字同源占比 | 40% | **94%** | — | 达标（契合「双字出自同一首诗」定位） |
| 跨输入重合率 | 1% | **4%** | <20% | 达标 |
| 八字匹配度 | 90% | **90%** | ≥60% | 达标 |
| 偏好生效度 | 4% | **12%** | <50% | 达标 |
| 语境义项覆盖 | 100% | **98%** | — | 达标 |
| 换一批变化 | 3% | **17~27%** | <90% | 达标 |
| 用字集中度（不同字） | 329 | **273** | — | 略降 |
| **高频常客** | 3 次 | **4~5 次** | ≤3 | **未达标** |

### 8.4 未达标项的诚实说明：常客 4~5 是数据上限，非调参可解

穷举了三个方向，均无法在保持质量的前提下压回 ≤3：

1. **全喜神层配额**（0.5 / 0.6 / 0.7 / 0.8）：常客恒为 5~7，无改善。
2. **用神加分**（0 / 10 / 20 / 30 / 60）：常客恒为 4~5，无区别。
3. **扩大组合预算**：`RANDOM_BUDGET_FACTOR` 20→160、`COMPOSE_CAP` 1200→6000，
   池子从 876 涨到 1453，但**同源名条数恒为 326~459，一条不涨**（涨的全是单字名）。
   说明同源池被源数据硬顶，不是配置问题。

结论：**质量与多样性在当前源数据下是一对硬约束**。要同时拿到
「Top30 无弱名」与「常客 ≤3」，必须**扩源数据**（更多诗词/条目 → 更大的同源池）。
这与既有的残留瓶颈一致（女性向诗词仅 43 条、寓意关键词偏窄富集弱）。

**当前取向：质量优先。** 理由——一次整改后的 44% 弱名率（「李财情 / 李殷足 /
李同刚 / 李谨刚」）是用户可直接感知的伤害；而常客 5 意味着一批**好名字**
（李素秋 / 李楚秋 / 李城坚）在 18 组不同生日里被多组选中，本身是合理的
（好名字对多个五行组合都成立）。如需切回多样性优先，把
`STRATIFY_QUALITY_BAND` 置 0（并相应下调温度）即可，无需改代码。

### 8.5 工具

- `scripts/eval_naming.py`：新增「质量分布 / 同源占比」两行指标；
  支持 `NW_TEMP` / `NW_BAND` / `NW_YONG` / `NW_FULL` / `NW_POOLF` 环境变量临时覆盖参数。
- `scripts/sweep_stratify.py`：参数扫描（温度 × 用神加分 × 带宽）→ 质量/多样性对照表。
- `scripts/diag_pool_quality.py`：候选池双峰结构 + 组合预算扩池上限验证。

## 九、2026-09-21 女性向语料扩容（数据层，唯一能解「质量 ↔ 多样性」硬约束的路径）

> 起因：第八节已证明「同源名池被源数据硬顶在 326~459 条」，质量与多样性无法双赢。
> 同时体检发现女性请求的结果最低分只有 40（男性 58）。

### 9.1 一个被纠正的判断：不是「只有 43 条可用」

原判断以为女性池枯竭是因为「女性向诗词仅 43 条」。实测（`scripts/diag_gender.py`）：

| | 匹配出处 | 其中女 | 其中中 | 同源名池 | 结果 min |
|---|---|---|---|---|---|
| 男 | 394 | 112（男） | 282 | 242 | 58 |
| 女 | 330 | **48** | 282 | **186** | **40** |

`get_by_gender("female")` 取的是「女 + 中」而非只取女，实际有 330 条可用。
真正的问题是**女性专属只有 48 条**，被 282 条「中」（多为经史子集/诗经的男性气质条目）稀释，
导致女性路径的同源名池只有 186 → 触发了质量带宽的安全阀 → 40 分级弱名漏出。

### 9.2 扩容手段：独立管线（不动已标注的 470 条）

⚠️ **关键工程约束**：`annotated.jsonl` 按 `raw_{NNNN}` 序号关联。
重跑 `normalize_corpus.py` 会让 id 整体位移、使已有 470 条标注全部错位。
因此新增材料走**独立文件 + 独立 id 前缀**，再由 `merge_poetry.py` 增量并入：

```
normalize_female_corpus.py  → data/poetry/raw_female.jsonl      （id: fem_NNNN，380 条）
llm_annotator.py --input raw_female.jsonl --annotated annotated_female.jsonl ...
                            → data/poetry/annotated_female.jsonl（374 条，0 失败）
merge_poetry.py --annotated annotated_female.jsonl --raw raw_female.jsonl
                            → 增量 append 进 poetry.json（按 (source,title,text) 去重）
```

取材（`.corpus` 里此前**完全未使用**的部分）：

| 新来源 | 取材 | 原语料量 | 预筛 |
|---|---|---|---|
| 宋词（扩容） | 全宋词 21053 首中筛「女性词人 + 婉约派代表作者」 | 3709 首 | 170 |
| **五代词**（新） | 花间集 11 卷 + 南唐词（李璟/李煜/冯延巳） | 542 首 | 150 |
| **清词**（新） | 纳兰性德诗集 | 258 首 | 60 |

新增来源需同步四处（缺一处即失效）：
`validate_poetry.SOURCE_ENUM`（R7 门禁）、`naming_options.STYLE_OPTIONS[*].source_preference`
（风格 Tier 判定）、`miniprogram/utils/api.js`（前端镜像）、`poetry_database` 文档串。
前端镜像由 `tests/test_frontend_mirror.py` 强制校验。

### 9.4 代价与后续

- **语境义项覆盖**已由 73% 恢复到 **98~100%**：增量补跑 `sense_annotator.py`
  （断点续跑，只标注新增对），累计 **2476/2476** 对，本轮成功 1186、失败 0。
- 女性仍略低于男性（min 55 vs 58），但已从「安全阀被绕过」变为正常区间；
  继续拉平需再扩女性源（玉台新咏、女性诗人专集）。
- 女性向取材本身仍偏「花/妆/罗/钗」物象，**格调治理**（避免艳情化）需要人工抽检。

## 10. 性别口径贯穿「出处择优」（2026-09-06 修）

### 10.1 问题

起名有两条路径：

| 路径 | 出处从哪来 | 是否过性别 |
|---|---|---|
| 策略1 同源组名 | `_available_source_entries(gender)` | ✅ 过滤（男→男+中 / 女→女+中） |
| 策略2 随机组合 | `_find_best_entry()` 走 `get_by_char` **全库检索** | ❌ **不过滤** |

后果：女性请求的随机路径名字会被挂上**男性向出处**（反之亦然）。
不只是「标签不好看」——出处的 `imagery`/`scene` 会参与偏好匹配，
且出处进入 `yunwei.score()` 的 provenance 项，直接污染主排序键。

实测（4 组生日 × Top20，苏姓）：女性结果中 `gender=男` 的出处占 **15%**，
男性结果中 `gender=女` 占 **12%**。

### 10.2 修法

新增 `_gender_tag()` / `_filter_by_gender()`，让 `_find_best_entry()` 与
`_find_entry_for_char()` 接收 `gender`：**在本性别 + 中性口径内择优，收窄后为空则退回全集**。

- 用「收窄后为空退回全集」而非硬堵：冷门字的同源出处可能只有一条且带异性标签，
  硬堵会导致该名字挂不上出处 —— 产品核心是「有据可循」，宁挂准确出处也不错失。
- 调用点补传 `gender`：`_compose_names` 随机路径 + `generate_meaning_detail`
  （两处必须一致，否则列表页与详情页出处不一致）。

### 10.3 效果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 女性结果 `gender=男` 出处 | 15% | **8%** |
| 女性结果 `gender=女` 出处 | 24% | **42%** |
| 男性结果 `gender=男` 出处 | 19% | 16% |
| 主口径（min/同源/跨输入重合/八字/偏好） | — | **无回退** |

残余 8% 来自「同源出处唯一且带异性标签」的退回全集路径，属设计内保留。

### 10.4 尚未解决（待拍板）

性别标签在语料里极度失衡：男 131 / 女 262 / **中 480**。「中」占 55%，
且大量「中」条目其实是男性观感（如《龟虽寿》「壮心」、《塘上行》「延寿」），
所以女性结果里「中」仍占 50%，会产出「苏立中/苏廉正/苏壮心」这类偏男性观感的名字。
**根治需要重新审校「中」条目的性别标注，而不是改算法。**


## 11. 同源名两字必须「既成对、又宜作名」（2026-09-22 修，核心体验）

用户原话：「名字在一个出处选择的两个字，不应该是单纯的取了两个字出来，
虽然是从这里取的，但是也应该适合做名字」。

这句话点破了同源路径的**根本缺陷**：出处给的是**一串推荐字**（「一袋好字」），
组合层对它做 **C(n,2) 全交叉**，于是「从一条出处取的」被偷换成了「从一条出处里抠两个字」。
名字与出处之间只剩「两个字都在原文里」，没有任何「这两字合起来像不像名字」的判断。

### 11.1 问题量化（改造前实测）

| 维度 | 实测 | 说明 |
|---|---|---|
| 跨句拼接占比 | **63.8%**（1080 名） | 两字分处两个分句，甚至有一字不在原文（靠意象标签推） |
| 四档韵味分中位数 | **全部 66** | 「婵娟」（原句成词）与「萸橘」（跨句硬拼）同分 → **评分器对组合成立度失明** |
| 出处内部字对分布 | 3378 对中：相邻 14.4% / 同句 20% / **跨句 65.5%** | 873 条出处 C(n,2) 的天然结果 |

结论：问题不在排序（分数已失明），而在**候选生成**——坏组合是在组合阶段就产生的，
排序阶段再精细也救不回来。

### 11.2 改造分两层：规则层 + 语义层

**第一层（规则层）——组合成立度分档**，解决「原文里不成对」：

| 档位 `kind` | 判据 | 出处分 | 说明 |
|---|---|---|---|
| `adjacent` | 两字在原文中**相邻成词** | 35 | 真正的取典（婵娟/望舒） |
| `same_clause` | 同一分句内不相邻 | 30 | 仍可解释（灼华/清扬） |
| `cross_clause` | 分处两个分句 | 22 | 机械拼接，仅略高于单字出处 |
| `char_absent` | 有字不在原文 | 20 | 靠意象标签推的，最弱 |

实现：`yunwei_scorer.pair_cohesion(a,b,text)` 判定档位 →
`COHESION_SCORES` 给分；出处分从「同源一律 35」改为**按成立度分档**。
另在 `_stratified_sample` 入口加 `_cohesion_window` 类别门槛：
成对候选足够多（≥ k×2）时**只从 `adjacent`/`same_clause` 里抽样**，
把跨句拼接挡在候选池外（用类别门槛而非分数带宽，避免把跨句压到和单字出处同分而误伤）。

**第二层（语义层）——LLM 字对标注**，解决「成对但不宜作名」：

第一层只能判「在原文里成不成对」，判不了「成对的两个字像不像名字」。
「圣人」「教多」「用财」「壮心」「呦鹿」在原句里都是成词的，却完全不像名字。

新增 LLM 标注管线：
- `scripts/prompts/pair_prompt.py` + `scripts/pair_annotator.py`：逐条出处调 LLM，
  从原句里挑出**可直接作双字名**的组合，产出 `data/poetry/name_pairs.json`
  （断点续跑 `pairs_done.json`）。
- 服务端硬校验 `normalize_pairs`：两字必须在原文、同分句、两字不同、非功能字。
- `scripts/pair_review.py` 第二道闸：批量 LLM 复核，剔除**专名/称谓/成语/具体妆具器物**
  四类，并设 `PROTECTED` 保护名单（修远/望舒/素秋/琼玉/清扬/玉瓒/灼华等）防止误杀。

| 标注产出 | 数量 |
|---|---|
| 覆盖出处 | 699 条（有字对 558 条，86%） |
| 字对（含重复） | 965 对 |
| 字对（唯一） | 805 个 |
| 复核剔除 | 167 个（972 → 805） |

**引擎接入（关键：分两路）** —— `compose_from_entry` 双字路径：

1. **有标注的出处 → 只产出标注字对**，放弃全交叉。
   这是「不要单纯抠两个字」的落点：全交叉只要保留，`圣人`/`壮心`/`呦鹿`
   这类「原句成词但不宜作名」的配对仍会漏出来 —— 语义判断只有标注能提供。
2. **无标注的出处 → 退回按成立度排序的全交叉**，功能不降级到无候选。

配套：`_order_two_chars` 在成词时按词序输出（「婵娟」不倒成「娟婵」）；
标注字对可能用到推荐字之外的字（如「修远」的「远」），
故 `compose_from_entry` 把这些字补进可用字，`_provenance_score` 的「同源」判定
也改为 `recommend_chars ∪ name_pairs 用字`；`sense_annotator.build_tasks`
同步纳入 name_pairs 用字，避免语境义项覆盖率掉档。

### 11.3 效果（补标前实测，苏姓 2020-08-20）

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 机械拼接（跨句 + 字不在原文） | 63.8% | **0%** |
| 相邻成词占比 | 14.4% | **51.5%** |
| 韵味分下限 | — | ≥ 50 |
| 同源率 / 跨输入重合 / 换一批差异 / 偏好生效 | — | 100% / 7% / 40% / 19% |

出现的名字（女性）：望舒 81 / 敏慎 66 / 玉立 64 / 窈窕 58 / 锦安 57 / 幽意 55；
（男性）：敏慎 66 / 金镂 65 / 时语 63 / 天远 62 / 长闲 59 / 楚山 58。
均为「原句成词 + 像名字」，观感问题解决。

### 11.4 上线前的三道补漏（同轮实测发现，缺一不可）

抽样审计仍有漏网名：`陈壮心`（正是「成对但不宜作名」的典型）、`陈荔枝`、`苏福禄`。
新增诊断脚本 `scripts/diag_pair_leak.py`（按结果自带出处原文精确反查、按成因归类）
定位出**三个独立漏洞**，逐个补掉：

**漏洞① 策略1 退回全交叉 —— 40% 的漏网来自这里。**
初版只做了「有标注 → 只出标注字对」，但**「标注跑过、字对被复核清空」的 141 条出处**
仍会走 `annotated = [] → falsy → 全交叉` 分支，把复核刚剔掉的组合（荔枝/长安/寿年）重新拼出来。
→ 新增 `name_pairs_known` 字段区分两种「字对为空」：
`known=True` 且空 = 语义层判定此出处无可作名组合 → **不产出双字名**；
`known=False` = 从未标注（新增语料）→ 保留全交叉兜底，功能不降级。

**漏洞② 策略2 随机组合绕过语义层 —— 60% 的漏网来自这里。**
随机组合原本用 `_same_source_partner()` 找搭档，而它取的是
「出现在同一条出处 `recommend_chars` 里的字」—— **那正是「一袋好字」旧机制本身**。
于是「圣人」「寿年」「教多」全部复活，且 `_find_best_entry` 会给它们随便挂一条同源出处。
→ 新增 `PoetryDatabase._build_pair_index()` / `approved_partners()` / `entries_for_pair()`，
`_same_source_partner` 改为**只从已批准字对取搭档**，取不到就 `continue`（不退回机械拼接）；
出处改为优先挂 `_pair_entry()`（该字对**真正被批准**的那条），保证详情页里两字成对。

**漏洞③ 同字对反序重复（观感像 bug）。**
不同出处的原文语序不同，`_order_two_chars` 会分别按各自语序输出，
于是 `杨柳 / 柳杨`、`香红 / 红香` 同时上榜。
→ 最终采样阶段加 `_dedupe_reverse_pairs()`，只保留韵味分更高的那个语序（单字/叠字不受影响）。

修复后 `diag_pair_leak.py` 复测：**239/240 同源双字名全部落在标注字对内（99.6%）**，
`annotation_empty` / `no_annotation` / `not_paired` 均为 0。

### 11.5 补标注：救回被复核清空的 141 条出处

漏洞①的正面代价是候选池缩水：`_stratify` 实测常客 7 次（原 4~5）、Top20 用字占比 28%（原 20%）。
而 141 条被清空的出处里并非全都无药可救 —— 例如《关雎》「窈窕淑女」的 `窈窕`
是**复核误杀**（判为「称谓/固定语」），复核脚本**原地覆盖、无备份**，原始字对已丢失。

→ 给 `pair_annotator.py` 加 `--only-empty` 补跑模式：
- 只重跑「已标注但字对为空」的条目；
- 把 `pairs_review.json` 的剔除清单作为**硬排除**传进提示词（服务端 `normalize_pairs` 同样拦截）；
- **黑名单必须先扣掉 `PROTECTED`**，否则「窈窕」会被自己的黑名单永远挡住；
- 第一轮空手则追加一次「上一轮全不合规，请换字对」的二次提示。
- 同时把实测误杀的经典词补进 `pair_review.PROTECTED`：窈窕 / 伊人 / 锦瑟 / 霓裳。

结果：《关雎》`poem_0010` 恢复 `窈窕`；仍然为空的条目说明该出处确实不宜作名，
保持为空即可（引擎侧已不会退回全交叉）。

另修 `pair_review.py` 的**不可逆覆盖**缺陷：复核前先把原文件备份为 `name_pairs.json.bak`
（「窈窕」丢失的直接原因就是原地覆盖且无备份），并在提示词侧把保护名单从黑名单中扣除。

| 指标 | 本轮改造前 | 最终 | 判定 |

| 同源双字名落在标注字对内 | 63.8%（机械拼接） | **99.2%** | ✅ |
| 机械拼接漏网（annotation_empty / not_paired） | 大量 | **0** | ✅ |
| 韵味分下限 | 50 | **55** | ✅ |
| 韵味中位 / 低于 50 分条数 | 63 / 0 | 63 / **0** | ✅ |
| 同源占比 | 100% | 100% | ✅ |
| 八字匹配度 | 90% | 90% | ✅ |
| 语境义项覆盖率 | 100% | **100%** | ✅ |
| 跨输入重合率（目标 <20%） | 7% | 14% | ✅ |
| 换一批变化（目标 <90%） | 40% | 50% | ✅ |
| 偏好生效度（目标 <50%） | 19% | 34% | ✅ |
| **高频常客（目标 ≤3）** | 4~5 | **7** | ⚠️ 退步 |
| **Top20 用字占比** | 20% | **33%** | ⚠️ 退步 |
| pytest | 69 | **75** | ✅ |

**取舍说明（重要）**：多样性两项退步是**语义层的必然代价**，不是 bug。
699 条出处里只有 **529 条**有「宜作名字对」（170 条是议论句/哀伤句，本就无适合作名的组合）。
旧实现用 C(n,2) 全交叉把 170 条空出处的机械拼接也算进候选池，虚高了多样性。
**真要提高多样性，只能扩源数据（加诗句），不能靠放宽语义门槛。**

**已验证无效的扩产路径**：给 `pair_annotator.py` 加 `--topup` 增补模式（保留旧字对、
另请 LLM 追加）。小批 20 条产出 2.2 倍字对，但**约 75% 是凑数**（城隅/嘉宾/鼓瑟/雉鸠），
因为一句话里的好字对本就有上限 —— 实测 699 条出处平均仅 **1.56 对**（提示词允许 4）。
结论：**字对库存受语料封顶，不能靠追问扩充。**

**调参亦无效**：温度 36→80→160、全喜神层配额 0.8→0.6→0.45 两组旋钮扫描，
常客在 7~9 之间不动，且降配额会同时把八字匹配度从 90% 拉到 73%。故保持默认值。

### 11.7 兜底：人工硬黑名单（补 LLM 复核的召回缺口）

上线前抽 API 实测，`苏壮心` 仍被判定为 **annotated** —— 说明 LLM 复核有**召回缺口**：
它漏掉了「壮心」（《龟虽寿》「烈士暮年，壮心不已」），而这个词正是用户
「成对但不宜作名」批评的原型。逐条排查后确认漏网还有：
中立（中天下而立）、用明 / 用恩（虚字组合）、知己（关系称谓）、
石上 / 盈岸（方位）、社方（祭祀）、新燠（生僻物候）、花语。

语义漏网无法只靠调提示词根治（提示词里早已把「壮心」同类写进禁令，仍然漏），
故按项目既有的「事件负面字黑名单」思路，在 `pair_review.py` 加一道
**确定性下限** `BLOCKLIST`（人工维护，命中即剔除，不看 LLM 脸色）：

- 论断/志向：壮心、中立、廉正、固朝、君子、圣人、大知、淑女
- 功能/虚字：用明、用恩、用财、教多、在志、里志、有土、社方
- 关系/称谓：知己、妻子、天子、诸侯、呦鹿
- 物产/方位/俗语：荔枝、福禄、延寿、年寿、红萸、黄橘、石上、盈岸、新燠、花语、长征

配套 `--blocklist-only` 模式：**只应用硬黑名单、不调 LLM**，幂等无随机性
（避免为了删 12 个词而重跑一次有随机性的全量复核，把已通过的字对又抖掉）。
同时把这些反面例子同步进 `pair_prompt.py` 的禁令示例，减少未来重生成。

剔除后 **817 对 / 525 条**；API 复测黑名单词不再出现。

**残余问题（不属本轮范畴）**：女性请求仍会出 `宝兴/正兴/厉高` 这类偏男性观感的名字，
根因是第十节记录的**性别标签失衡**（「中」占 55% 且大量实为男性观感），
需要审校「中」条目的性别标注，不是改字对算法。
