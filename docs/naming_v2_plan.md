# 名堂 v2 起名逻辑升级方案

> 基于知乎高赞起名逻辑研究 + 用户四项需求，2026-09-06

## 一、需求与决策记录

| 需求 | 决策 | 落地位置 |
|---|---|---|
| 1. 研究知乎起名逻辑 | 提炼「姓氏+音韵+字义联动」三层共识 | 本方案第一节 |
| 2. 评分规则 + 解锁 | 解锁「深度寓意解读」，分享解锁已实现，广告通道后续接入；按「起名任务批次」单次解锁 | 前端 detail 页 + `/name/meaning` |
| 3. 先选字再起名 | 两种交互都保留（选字点选 / 自动展示），按数据迭代 | 新增 `/recommend-chars` + `selected_chars` |
| 4. 名字结合姓氏 | 谐音歧义硬排除 + 姓氏声调引导 + 本义冲突检测 | `surname_fit.py` + 门槛层 |

## 二、知乎起名逻辑借鉴结论

核心共识：**姓氏 + 音韵 + 字义联动**，与「韵味核心 + 漏斗筛选」方向一致，不需推翻。

补齐的四块短板（= 需求 4）：
1. **姓氏谐音歧义检测**（安全底线，硬排除）：杜子腾→肚子疼、史珍香、吴德→无德、杨伟→阳痿、毕云涛→避孕套
2. **姓氏本义冲突**（高危项硬排除）：朱+红重复、白+云贬义
3. **姓氏声调参与选字**（组合优化）：姓+名避免三连同调/全平全仄
4. **姓氏谐音借力成词**（S1 加分，P1 暂缓）

## 三、实施设计

### 后端（本轮完成）

**1. `app/services/surname_fit.py`（新增）**

- `is_meaning_conflict(surname, given_name)`：姓氏禁配字规则 → 硬排除
- `tri_tone_conflict(surname, chars)`：姓+名三连同调检测 → 组合阶段预检

**2. `data/dict/surname_taboo.json`（新增）**
- 负面谐音词表（可扩充），约 25 个高危项

**3. `naming_engine.py`（修改）**
- `_pass_gate` 增加：谐音歧义 + 本义冲突硬排除
- `_compose_names` 组合阶段：三连同调预检（优化，不改变结果正确性）
- 新增 `recommend_chars()`：八字→喜用神→分组推荐选字
- `generate_names()` 支持 `selected_chars`（用户点选字限定范围）

**4. `schemas.py` / `routes.py`（修改）**
- `NamingRequest` 加 `selected_chars`
- 新增 `POST /recommend-chars`

### 前端（本轮完成，广告通道留 TODO）

**1. 分享解锁深度寓意（`pages/detail`）**
- 深度寓意（多层余味）接入 `/name/meaning` 接口，懒加载 LLM 解读
- 解锁粒度 = 起名批次：`wizard` 起名 / `result` 换一批时生成 `lastBatchId`

- 未解锁时展示「分享解锁」遮罩（`button open-type="share"`）；解锁后展示字面/出处/余味三层

- 用户点选（最多 6 字，可跳过），所选字作为 `selected_chars` 传给 `/generate`

## 六、候选多样性修复（2026-09-06 追加，用户反馈「推荐名字来来去去都是那些」）

### 根因（四个，层层叠加）

1. **随机性为零**：组合策略1「同源组名」确定性遍历全部 499 首诗词，策略2「随机组合」触发条件是 `候选<30` 但策略1 早就超额 → 随机组合永不执行；最终按韵味分固定截取前 30，同参数多次调用 100% 一致。
2. **姓氏几乎不参与**：韵味分 100 分里姓氏协调 S 仅占 15，且「成词成典/意象呼应」对多数姓命中不了 → S=0，姓氏只是前缀。
3. **偏好几乎无效**：`meanings` 只 sort 不筛集合，`_rank_poems` 里 meanings 不参与 tier → 智慧/健康/默认三组结果一字不差。
4. **数据质量**：本草/诗经推荐字混入药名（枸杞/茯苓/甘草）、鸟兽名（雎/鹿）、浮萍（苹）等不适合做名字的字。

### 修复（`naming_engine.py` + 数据）

1. **随机性**：`_compose_names` 策略1 tier 内 `random.shuffle` 诗词 + 总量封顶；策略2 随机组合改为**始终参与**（预算 40+）；新增 `_weighted_sample` 加权随机采样（从韵味分高分池软加权不放回抽 max_results 个）。
2. **姓氏参与**：新增 `_char_affinity`（姓氏意象呼应 + 偏好命中），候选字与同源字按亲和分排序；随机组合用 `_weighted_char_choice` 偏向姓氏/偏好匹配的字。
3. **偏好软加权**：`_rank_poems` 的 `tier_of` 让 meanings 命中的诗词进 tier A（优先引入）。
4. **数据清理**：`source_entries.json` 去掉「枸/茯/草」药名原字（保留杞/苓/甘）；`poetry.json` 6 条诗去掉「雎/苹/鹿/窕」等非名字用字。

### 效果验证

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 同参数连续调用 | 100% 一致 | 每次 top10 均不同 |
| 不同姓氏重叠 | 近 100% | 与李姓重叠 4~9/30（13%~30%） |
| 寓意/风格偏好 | 与默认完全相同 | 结果有差异 |
| 药名/怪字（枸杞等） | 出现在 top10 | 全部清除 |
